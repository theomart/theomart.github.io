Why in your repo and not in a classroom

What separates a team that gets something out of Claude Code from a team that has licences is not knowledge of the tool, that takes a week. It is what is written around it, in the repo, CLAUDE.md, skills, hooks, permissions, and above all whether the agent actually follows it. A subfolder’s CLAUDE.md, for one, only loads when the agent opens a file in that folder with its Read tool. A public issue tried 27 other ways in, cat, grep, find and heredoc included, and none of them triggers it. Another case, Claude Code only falls back to AGENTS.md when there is no CLAUDE.md, and a personal CLAUDE.local.md is enough to cut that fallback, and with it every shared instruction, without a single warning.

None of that shows on a sample project, which has no debt, no odd convention inherited from 2019, and no flaky test everyone works around.

A catalog Claude Code course is the right format when a team is discovering the tool. Across the forty or so French catalogs my agents went through in August, only two put hooks and skills on the program, and none covers secrets handling when an agent is the one reading the repo. The day I sell only makes sense once agents have been in the repo for a few months and nobody can say what it changed in what ships.

What happens during the day

In the morning we take three or four tickets from the current sprint, real ones, and push them through the agent together. Bare first, CLAUDE_CODE_SAFE_MODE=1 starts it with no CLAUDE.md, skills, hooks or MCP, and we look at where it fails on its own. That usually says more than rereading the CLAUDE.md written a year ago, it shows what is missing. We also compare machines, every Claude Code install caches hundreds of settings served by the vendor, and two developers on the same team can be running under different instructions without knowing it, which checks out in one command on each machine.

For every guard your team thinks it has, a nested CLAUDE.md, a hook, a rule that denies a sensitive file, we check whether it is scoped to a tool or to an effect. A rule declared on one tool does not follow the agent when it reaches for another to get to the same place, and that is what gets checked first, before writing anything new.

In the afternoon your developers write the repo’s CLAUDE.md files, not me, during the session. We wire up the hooks that are useful at your company and test them for real, a hook that exits with code 1 reports an error but lets the action through, only code 2 blocks it. We finish on cost, with the numbers from your own account. The tool estimates tokens at list price rather than your contract rate, and no metric tracks review time, so we rebuild it from your own timestamps.

In the evening what was written is committed to your repo. There is no slide deck to take home, the material is your code.

Questions I get before a booking

Does the team need to be using Claude Code already?

Yes, for at least a few weeks. If nobody has opened the tool yet, take a course built for beginners, Zenika’s for instance is sold with no prerequisites at all and costs less than my day. Mine is wasted until someone has hit a concrete friction worth bringing to the table.

We are on Cursor, Codex or Copilot, does it still work?

Yes. I work mostly with Claude Code, but what we write during the day, repo rules, hooks, pre-merge checks, carries over. Shared instructions can live in AGENTS.md, an open format now stewarded by the Linux Foundation, which Cursor, Codex, Copilot and Claude Code can all read.

On site or remote?

Both. On site around Paris, remote anywhere in France and Europe, screen shared and repo open on both sides. Claude Code has no shared session across two accounts, so remote work goes through the shared screen, and I ask that the team sits in the same room on your side, a day across twelve Meet windows writes nothing.

How many developers?

Between four and fifteen. Below four, take an hour of office hours instead. Above fifteen, we split it into two days.

What do you need beforehand?

Read access to the repo a week ahead, and the list of tickets for the sprint. I read the repo before I come, and we start from what I saw there rather than from your assumptions.

What about the NDA and security?

I sign yours. Nothing leaves the repo, I keep no copy of the code, and I am under NDA myself on a mission at a CAC 40 company. On the tool side, WebFetch sends Anthropic the domain name of every page it is about to read, for a preliminary check. A setting turns it off, and we set it together if your policy requires it.

What is left a month later?

The committed files, written by your developers, and a habit, reviewing the CLAUDE.md like code. The gain fades if nobody looks after it, which is why the office hours format exists, to come back one hour a month without redoing a full day.

Is this an official Claude Code training?

No. The official course exists, Claude Code 101, free on Anthropic’s learning platform. I have no link to Anthropic, no certification and no partnership. What I sell comes from nine years of ML in production and daily use of coding agents in real company repos.
